# 06_ROADMAP — 6단계 로드맵 + DoD

> 순서 근거: 사용자 확정 우선순위 — 플랫폼화 구조 먼저, 입체도형 완성, 스캐폴딩+추적 인프라, 교사 도구는 마지막.

## Phase 1 — 리포 플랫폼화 (기반)
Vite+TS 모노 구조(02) 셋업, R010 산출물 이관(engine-3d TS화, 셸·9챕터 ChapterModule화), legacy `src/*.part` → `archive/`, Actions→Pages 배포.
**DoD**: ① 9챕터 전부 R010과 동작 동일(챕터별 수동 체크리스트 통과) ② `npm run dev/build` 만으로 개발·배포 ③ 새 챕터를 인터페이스 구현 1파일로 추가 가능함을 더미 챕터로 증명.

## Phase 2 — 홈 + 멀티 랩 셸
탐구랩 홈(랩 카드, 로컬 진행 표시), 해시 라우팅, PanelHost·PlayStep 시퀀서를 셸로 승격, 브랜드 적용(07).
**DoD**: ① `/#/` 홈 ↔ `/#/solid` 랩 전환 상태 보존 ② 랩 메타만으로 홈 카드 자동 생성 ③ 태블릿(터치) 스모크 테스트 통과.

## Phase 3 — 입체도형 콘텐츠 완성 (백로그 이식)
전개도 접기/펼치기 3D 애니메이션(힌지 트리 보간), **정다면체 5종 전 유의미 전개도 변형**(정육면체 11종 포함 — 스패닝트리 생성기 + 합동 중복 제거 파이프라인), 오일러 증명 타임라인.
**DoD**: ① 5종 각각 변형 목록 완비(사면체 2·정육면체 11·정팔면체 11·정십이면체/정이십면체 43,380은 대표 변형 큐레이션 — 큐레이션 기준 문서화) ② 임의 변형 선택→접기 애니메이션 동작 ③ 데이터는 기존 `nets` 스키마 추가 필드로만.

## Phase 4 — 스캐폴딩 룰 엔진 (오프라인 완결)
Predicate 룰 엔진, ScaffoldTree 로더, 학습 노트 연동, 챕터 3개 이상에 실제 트리 작성(depth 0~4), Stage2D 계약 확정(구현 아님).
**DoD**: ① 트리 JSON만 추가해 새 스캐폴딩 배포 가능 ② 3챕터에서 오답 패턴별 분기 ≥3개씩 ③ 백엔드 없이 정적 힌트로 완전 동작 ④ Stage2D 인터페이스 동결.

## Phase 5 — 추적 + 백엔드
IndexedDB 적재→배치 동기화, 교사용 JSON 내보내기, VPS Docker 스택(05) 배포, LLM 힌트 프록시 + 캐싱.
**DoD**: ① 04 스키마 그대로 저장·동기화·dedupe 검증 ② 백엔드 다운 시 무결 폴백 ③ 동적 힌트가 정적 폴백 대비 nodeId 문맥 반영 ④ 수집 범위가 branch 경로+깊이 외 0필드임을 코드 리뷰로 확인.

## Phase 6 — 검증·다듬기
실사용(자습 학생 + 1:1 교사) 파일럿, depth 분포·fail-branch 데이터로 트리 개정, 모션·터치 폴리시, 접근성 패스.
**DoD**: ① 파일럿 학생 1명 이상이 개입 없이 챕터 3개 COMPLETE ② 교사가 내보낸 traversal JSON으로 막힌 지점을 특정 가능 ③ 개정된 트리 버전 배포(treeVersion 증가) 이력 1회 이상.

## 명시적 비범위 (이번 로드맵에서 안 함)
평면도형 등 타 단원 콘텐츠, 교사 프리셋/출제 도구, 계정 시스템, LLM의 정답 판정.
